# هدف القسم: تجهيز الإطلاق (GM-006، وضع التجهيز فقط)

التاريخ: 2026-09-27. لا نشر، لا حسابات، لا مفاتيح.

## الهدف الواحد
يوم يقرر صاحب المشروع الإطلاق، ينجز كل شي في جلسة وحدة: runbook واضح + أداة لإدارة روابط الشرائح + تصميم عدّاد اللمسات.

## المطلوب
1. **sys-architect** → `systems/LAUNCH-RUNBOOK.md` + `systems/tap-counter.md` + ملفه `sys-architect.md`:
   - runbook بخطوات مرقمة من قرار الإطلاق لين الموقع شغال: شراء الدومين، فتح الاستضافة (Cloudflare Pages أساسي حسب `systems/architecture.md`)، رفع `systems/shortlinks/dist/` و`website/` (افحص وش في `website/` وكيف ينضمون في موقع واحد بدون تعارض مسارات)، تغيير `config.json`، البناء، وفحص كل رابط (أوامر curl جاهزة). كل خطوة مكتوب جنبها: **صاحب المشروع** أو **احنا**. مع خطة رجوع لو صار خطأ، ووقت تقديري لكل خطوة («تقدير»).
   - عدّاد اللمسات: كيف نقيس الفتحات بدون IP وبدون بيانات شخصية. الخيارات (مثل: تحليلات الاستضافة المدمجة، Cloudflare Web Analytics، Worker بعداد، سجل خادم)، ولكل خيار: الدقة، الخصوصية، التكلفة (مصدر رسمي أو «غير مؤكد»)، ويش يتطلب. توصية واحدة، وتصميم محلي للعداد (شكل التقرير الشهري لكل شريحة، تمييز nfc/qr عن طريق `?src=`).
2. **sys-builder** → `systems/shortlinks/links-cli.js` + تحديث README + `sys-builder.md`:
   أداة node بدون مكتبات: `add <code> --client --place --dest`، `set-dest <code> <url>`، `cancel <code>`، `list`. تعدّل `links.json` (السجل الحقيقي؛ `links.txt` مخرَج)، وتعيد البناء بـ build.js، وتعتمد على حمايات build.js (ما تكررها بشكل يتعارض). ممنوع: كود مكرر، حذف منشور، تعديل كود ملغى بدون قصد. لو فشل البناء ترجع `links.json` لحاله قبل التعديل. خيار `--gen` يولد كود عشوائي آمن.
3. **sys-tester** → `sys-tester.md`: يجرب الأداة فعلاً على نسخة في scratch: كل أمر، الحالات الغلط، والرجوع عند فشل البناء؛ ويراجع الـ runbook خطوة خطوة: هل الأوامر تشتغل فعلاً محلياً؟ PASS/FAIL بمخرجات.

## ممنوع
تسجيل في أي خدمة، كلمات مرور، مفاتيح، أرقام حقيقية، أسعار بدون مصدر.

## معيار النجاح
الأداة PASS، الـ runbook ينقرأ وينفذ بدون سؤال، وكل معلومة خارجية بمصدر أو «غير مؤكد».
