# هدف القسم: نظام الروابط الثابتة `/t/<code>` (تكليف GM-002 / GM-003)

التاريخ: 2026-09-27. المكلِّف: المدير العام.

## الهدف الواحد
نظام روابط ثابتة `https://<domain>/t/<code>` يحوّل لوجهة العميل، يشتغل على استضافة ثابتة مجانية، وجاهز يوم يشتري صاحب المشروع الدومين (نغير متغير الدومين بس). ومعه تصميم مبدئي (ورق، بدون بناء) لإشعار «تشيك أوت» في باقة المضيف بدون كشف أي رقم جوال للضيف.

## المطلوب
1. **sys-architect** → `sys-architect.md` + `systems/architecture.md`: مقارنة الاستضافات الثابتة المجانية (مع مصدر رسمي لكل ميزة/حد، واللي ما تأكد «غير مؤكد»)، طريقة التحويل (ملف _redirects أو صفحات HTML ثابتة مع meta refresh)، شكل الكود، سجل الروابط، قاعدة «لا يُحذف رابط منشور»، الإحصائيات (عدد اللمسات بدون جمع بيانات شخصية)، وتصميم إشعار التشيك أوت (من يرسل، حد الإرسال، «تأكد قبل الدخول»، حذف رقم العاملة عند الإلغاء).
2. **sys-builder** → `sys-builder.md` + ملفات في `systems/shortlinks/`: سجل روابط (`links.csv` أو json) + سكربت بناء (Node أو Python بدون مكتبات خارجية) يولد مخرجات تشتغل على أكثر من استضافة (صفحة HTML لكل كود + `_redirects`) + صفحة بديلة للروابط الملغاة + صفحة 404. روابط تجريبية فقط (example.com). بدون حسابات أو مفاتيح.
3. **sys-tester** → `sys-tester.md`: يشغل سكربت البناء فعلاً، ويخدم المخرجات محلياً (مثلاً `python -m http.server`) ويختبر بـ curl كل كود: موجود، ملغى، غير موجود، حروف كبيرة/صغيرة، شرطة مائلة في الآخر. PASS/FAIL بمخرجات حقيقية.

## ممنوع
- التسجيل في أي خدمة، أو إدخال كلمة مرور أو مفتاح. الحسابات لصاحب المشروع.
- أي رقم جوال حقيقي.
- كتابة سعر أو حد خدمة بدون مصدر.

## معيار النجاح
- `node`/`python` build ينجح، والمخرجات تحوّل صح محلياً (sys-tester PASS).
- تغيير الدومين = تعديل سطر واحد.
- المعمارية فيها مصادر، واللي ما تأكد مكتوب «غير مؤكد».
