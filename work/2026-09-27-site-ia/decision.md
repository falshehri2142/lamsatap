# GM-040: تنظيم الموقع لجمهورين (المحلات والمضيفين) بدون لخبطة

المشكلة (صاحب المشروع): عندنا نشاطين مختلفين — مطاعم/كافيهات، وإيجار قصير/Airbnb. لو خلطناهم في صفحة وحدة، العميل يتلخبط.
المرجع: ui-ux-pro-max — `primary-action`، `content-priority`، `progressive-disclosure`، `deep-linking`، `nav-hierarchy`، `state-preservation`، `persistent-nav`.

## القرار: «بابين» — كل جمهور له طريقه
1. **الرئيسية = بوابة:** وعد واحد مشترك في البطل («قرّب جوالك، تنفتح الصفحة»)، وبعده مباشرة **بابين كبار واضحين**:
   - «عندي مطعم أو كافيه» ← صفحة **للمحلات**
   - «عندي شقق أو إيجار قصير» ← صفحة **للمضيفين**
   (البابين هم أقوى لحظة حركة: مسح/باركود يكشف كل باب.)
2. **صفحتين مستقلتين بروابط مباشرة** (`/restaurants` و`/hosts` أو ما يعادلها في موقع ثابت): كل إعلان وكل رسالة واتساب توصل للصفحة الصح مباشرة (`deep-linking`).
3. **كل صفحة تتكلم مع جمهورها بس** (`content-priority`، `progressive-disclosure`):
   - للمحلات: مشاكل المحل ← الحل ← عرض المنيو/التقييم الحي ← **حزمة المحل الكامل فقط** ← أسئلة المحلات ← زر.
   - للمضيفين: مشاكل المضيف (أسئلة الواي فاي 2 الفجر، التشيك أوت) ← الحل ← دليل الشقة الحي ← **باقة المضيف فقط** (مع خصم 5 وحدات فأكثر) ← أسئلة المضيفين ← زر.
   - **ما نعرض أسعار الجمهور الثاني** في صفحة جمهور.
4. **زر أساسي واحد لكل شاشة** (`primary-action`): واتساب برسالة معبأة حسب الصفحة — «أبغى حزمة المحل لمطعمي» / «أبغى باقة المضيف لشققي».
5. **القائمة:** «للمحلات» · «للمضيفين» · «كيف نشتغل» + زر واتساب (`nav-hierarchy`، `persistent-nav`). الخدمات الثانية (المواعيد، المعارض، بطاقات الأعمال) في قسم صغير «خدمات ثانية» تحت، مو في القائمة الرئيسية.
6. **صفحة الأسعار الموحدة (لو انبنت):** تبويبين «للمحلات | للمضيفين»، والتبويب الافتراضي حسب الصفحة اللي جا منها الزائر (`state-preservation`).
7. **الهوية وحدة للجمهورين** (أبيض وأسود، GM-039)؛ الفرق بالرسمة والمشهد (كوب/طاولة للمحلات، باب/مفتاح للمضيفين) مو بألوان مختلفة.
8. **الحركة لكل صفحة لها قصتها المثبتة:** المحلات: طاولة ← جوال ← منيو. المضيفين: باب ← جوال ← دليل.
