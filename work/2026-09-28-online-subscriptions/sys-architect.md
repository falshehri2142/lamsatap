# sys-architect — معمارية الاشتراك والدفع من الموقع (GM-052، تصميم فقط، بدون بحث ويب)
1. **التوصية: نعم بشرط** السجل التجاري (GM-002) وقرار الإطلاق (GM-006). الموقع يبقى ثابت على Cloudflare Pages (`systems/architecture.md` §التوصية)، والمنطق كله في n8n. نضيف Pages Function بسيطة لصفحة «اشتراكي» فقط.
2. **المسار:** رسالة تذكير (ب) فيها رابط → صفحة «جدّد اشتراكك» (ثابتة) → Pages Function تطلب من n8n (webhook محمي بسر مشترك) إنشاء **رابط دفع مستضاف عند البوابة** (hosted payment page أو invoice link) بمبلغ `renewal_price_sar` من الجدول، مو من المتصفح → العميل يدفع في صفحة البوابة. نحن ما نلمس بيانات البطاقة، فنبقى على أقل نطاق PCI (SAQ A تقريباً؛ **غير مؤكد** حتى تأكيد البوابة).
3. **الربط:** رابط الدفع يحمل `metadata.subscription_id` و`metadata.client_id` (بدون جوال ولا اسم). ضغط «جدّد وادفع» والدفع الناجح هو التأكيد الصريح: `renewal_confirmed_ref = payment:<invoice_no>` (§1.2).
4. **Webhook البوابة → n8n:** (أ) تحقق من التوقيع أو السر، (ب) **إعادة جلب الدفع من API البوابة بالمعرّف** والتأكد من الحالة `paid` والمبلغ والعملة والـ metadata، (ج) idempotency: لو `gateway_payment_id` موجود في `payments` نوقف بدون تكرار. بعدها: (ج1) فاتورة آلية (رقم متسلسل لحظة التسجيل، ما في تخطي) ← (ج2) Insert `payments` + سطرين `ledger` ← تطبيق التجديد (خطوة Form التجديد في (ب)) ← `owner-notify` تليجرام (GM-048) ← `client-send` بالفاتورة.
5. **تعارض لازم يحسمه المحاسب:** (ج2) اليوم يشترط موافقة صاحب المشروع قبل أي Insert. اقتراحي: دفعة البوابة المتحقق منها بالـ API تُسجل مباشرة بـ `owner_confirmed = gateway`، وصاحب المشروع يستلم تنبيه فقط. الإيراد يُسجل بالمبلغ الكامل، ورسوم البوابة قيد مصروف منفصل عند التسوية (قرار المحاسب).
6. **أعمدة جديدة:** `payments`: `gateway` و`gateway_payment_id` (مفتاح idempotency) و`gateway_fee_sar` و`settled_at`، و`payment_method` تزيد لها قيمة `gateway`. `subscriptions`: `pay_link_id` و`pay_link_expires`. **جدول جديد `login_tokens`:** `token_hash` (SHA-256 فقط، الرمز نفسه ما ينحفظ) و`client_id` و`expires_at` (+15 دقيقة) و`used_at` و`created_at`، ونمسح الصفوف المنتهية يومياً. لا جوال ولا IP (§1 ممنوعات).
7. **حساب بدون كلمة سر:** العميل يطلب الدخول برقمه. n8n يتأكد إن الرقم موجود في `clients.whatsapp`، ثم يرسل magic link موقّع (رمز عشوائي 32 بايت) على واتساب أو تليجرام عبر `client-send`، وما يرسل إيميل للعميل (§2.0). الرابط صالح 15 دقيقة ولمرة وحدة.
8. **جلسة «اشتراكي»:** الـ Function تبدّل الرمز بجلسة (cookie `HttpOnly; Secure; SameSite=Lax`، عمرها 24 ساعة، اقتراح). تقرأ من n8n webhook محمي بسر في Cloudflare env، ويرجع اشتراكات العميل وفواتيره فقط. الرد نفسه سواء الرقم موجود أو لا، ومعه حد للطلبات.
9. **مؤجل:** التجديد التلقائي من البطاقة (tokenization، البطاقة محفوظة عند البوابة) مؤجل. يحتاج موافقة مسبقة صريحة وتعديل الشروط §4 وقرار loyer. البداية دفع يدوي لكل فترة.
10. **الفشل:** webhook ما وصل → n8n يفحص روابط الدفع المفتوحة كل ساعة من API البوابة (اقتراح). مبلغ ما يطابق أو metadata ناقصة → لا تسجيل، وتنبيه لصاحب المشروع. الاسترداد = إشعار دائن عند المحاسب.
11. **غير مؤكد:** صيغة التوقيع وحقول metadata وروابط الفواتير تختلف من بوابة لبوابة (Moyasar وTap وغيرها)، وما بحثتها هنا. ودعم Data Tables في n8n لقيود unique للـ idempotency **غير مؤكد**، فنفحص قبل الـ Insert.
